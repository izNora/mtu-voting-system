
## Fresh setup
pip install -r requirements.txt

```bash
python3 -m venv .venv
source .venv/bin/activate
mysql -u root -p < database.sql
python seed.py
uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 4
```

Open:

- `/developer` — add majors and create accounts
- `/admin` — Major candidate management or Whole candidate management
- `/organizer` — Major Admins organize only their own Major; Whole Organizer organizes only Whole
- `/vote` — entered through a valid QR session

There is no leaderboard page in this version.

## Account roles

- `major_admin`: assigned to exactly one Major. Can manage that Major's candidates and start/end only that Major festival.
- `whole_admin`: manages Whole candidates only. Cannot use Organizer Dashboard.
- `whole_organizer`: starts/ends Whole festival and generates Whole QR codes. Cannot manage candidates.
- Developer credentials remain in `.env` and create the accounts above.

## Parallel festivals and QR isolation

Every voter row has a `major_id`. A QR generated by the IT Major Admin belongs to IT; a QR generated by the MC Major Admin belongs to MC. Both festivals may run at the same time without sharing voters, votes, QR counts, or QR folders.

QR folders are separated as:

```text
qr_codes/major_1/students/
qr_codes/major_1/teachers/
qr_codes/major_2/students/
qr_codes/major_2/teachers/
qr_codes/whole/students/
qr_codes/whole/teachers/
```

Teacher QR images keep the red horizontal marker under the QR.

## Vote replacement / cancellation

There is no DELETE vote request. Use:

```text
PUT /api/voter/vote/{title_id}
```

with multipart field `candidate_id`.

- `candidate_id > 0` selects/replaces the candidate for that title.
- `candidate_id = 0` temporarily clears the title selection while retaining the vote row.

A voter still cannot give two different titles to the same non-zero candidate.

## Fresh database

New installations use `database.sql`. If an existing installation was created
from an older package, apply the login-attempt migration once before starting the
updated backend:

```bash
mysql -u root -p voting_system < MIGRATION_LOGIN_ATTEMPTS_EMAIL_IP.sql
```

## Login attempt protection

Developer and Admin logins use two independent daily counters:

- normalized email address: maximum 3 failed attempts;
- client IP address: maximum 3 failed attempts.

The request is blocked with HTTP `429` until the next calendar day if either
counter has reached 3. A successful login clears that email/IP pair before it is
blocked. Expired rows are deleted at backend startup and before each login check,
so previous-day data does not accumulate. The calendar boundary uses
`LOGIN_ATTEMPT_TIMEZONE` (default: `Asia/Yangon`).

The backend uses `Request.client.host` and deliberately does not trust a raw
`X-Forwarded-For` header. Behind Nginx, Cloudflare, or another reverse proxy,
configure Uvicorn's trusted proxy/forwarded-IP setting so the resolved client
address is correct and cannot be spoofed.


## Combined festivals

The developer can create a Combined Festival from two or more existing majors.

Internally:

```text
individual major target = positive major_id
Whole target            = 0
Combined target         = negative combined_id
```

Example:

```text
IT = 1
MC = 2
IT + MC Combined Festival = -1
```

Combined QR codes are stored separately under `qr_codes/combined_<id>/`.

When a Combined festival starts, every member major is marked running. When it ends, every member major is marked completed. This prevents any member admin from changing the candidate list after voting has started.

Unrelated majors are independent and may run in parallel.
